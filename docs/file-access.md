# Windows 文件访问权限

文件工具权限与工具模式独立。文件模式保留 14 项工具，完整终端模式保留 21 项。完整终端模式始终使用当前 Windows 用户权限。文件根限制只作用于文件工具。

| 文件访问权限 | 行为 |
| --- | --- |
| Restricted | 文件操作的路径及解析后的实际位置都必须落在授权根内。普通目录与盘符根均可设为授权根。 |
| Full | 文件工具可跨本机盘符操作，访问仍受 Windows ACL、文件锁和路径安全规则约束。 |

本机盘符以引擎启动时的 Windows 盘符类型为准。UNC、映射网络盘、设备路径、流路径和扩展长度路径拒绝。普通空格、中文、大小写变化与合法的点路径由系统解析。受限根必须是已有本机目录，授权根自身及其祖先不得通过链接重定向。跨盘符移动复用已有全量拷贝、目标提交、源删除顺序。

文件工具禁止修改当前安装目录内的控制文件。此限制涵盖配置、管理器及引擎；安装内的测试工作区可独立写入。文件工具不能通过修改权限配置为自己提权。Windows 权限和部署目录的操作系统防护继续生效。

## 配置及生效

旧部署仅设置 `engine/allowed-root.txt` 时使用 restricted。它仍是受限根的唯一配置。候选版用独立的 `engine/access-mode.txt` 保存 `restricted` 或 `full`，缺失时取 restricted。非法值拒绝启动。切换模式保持原受限根，旧版忽略模式文件并继续用原根。授权根始终验证，以便切回 restricted。

TUI 操作 6 提供权限模式选择和受限根修改。开启 Full 需要明确确认。先停止相应实例，保存后下次启动生效。GUI/CLI 使用相同的 revision 和本地管理锁。状态中的实际权限来自当前隧道所启动的引擎，证据缺失时返回空值。完整访问在现有本地开发代理中拒绝，GUI、Gemini 各自的测试工作区仍受限；可用独立本地 stdio 进程验证四种组合。

## 分支交接

- GUI 从 `configuration.accessModes` 读取持久化目标，显示 `fileAccess.actual` 与 `fileAccess.target`，用 `access.set` 修改并展示确认和重启提示。
- Gemini 使用公共引擎的同一权限策略。适配层可以进一步缩小工具或文件范围；权限设置只走本机管理接口。
- 集成时先审查并合入候选分支，再让两条开发线合入同一个公共提交。现有 mode 字段和 14/21 工具数保持兼容。

## 验证与发布

工作区定向验证入口为 `node tests/m7-access.mjs` 及 `node tests/m7-access-managed.mjs`。MCP 冒烟和管理契约沿用现有入口。测试所需的锁定依赖、构建产物与本地代理程序应已经就绪。远程 ChatGPT 实调属于部署验收。

候选分支基于 M7 公共维护，正式 v1.0.1 应从 v1.0.0 建独立维护分支。单独修正旧版启动入口拒绝盘符根的分支可作为窄补丁，并复验旧 TUI 操作 6。双模式及实际状态依赖公共管理协议和新版引擎，移植时须单独评估配置迁移和降级；不直接发布 develop。
