# M7-B3 GUI：实际工具发现与连接管理

## 设计边界

B3 对外仍是原有 WPF GUI + PowerShell 5.1 单请求 JSON stdio 管理内核；仅增加 GUI 专属的只读 MCP 检测组件。未修改公共管理协议、MCP 引擎、OpenAI 传输实现、正式 v1.0.0、Gemini 工作区或系统代理。B4 凭据/网络设置、B5 版本升级、B6 扩展、B6.5 使用统计及 B7 产品发布均不提前实现。

## 只读工具发现

`gui/McpDiagnostics.cs` 用后台 Node 子进程调用 `gui/mcp-inspect.mjs`。后者使用仓库已有 `@modelcontextprotocol/sdk`，从独立 GUI 开发实例的 `engine/runtime/proxy-url.json` 读取仅限 `http://127.0.0.1:PORT` 的本地 MCP 地址。拒绝远端、非回环和嵌入凭据的 URL。

检测严格区分两套清单：

- **预期名称**：从同一已安装版本的 `engine/stdio.mjs --test-run` 独立建立（只枚举 `tools/list`），不假设工具名称仅由数量决定。终端模式额外建立文件模式基线目录以识别新增的终端工具。
- **实际名称**：向当前已启动的开发代理执行真实 MCP `initialize`、分页 `tools/list`，不执行工具调用。返回名称、数量、差集和检查时间。
- **工具验证**：把全部预期/实际工具名称逐一比对；即使数量相同，也能发现缺失与额外工具。禁止重复名称、重复游标和异常分页。真实调用单独通过 `tests/gui-mcp-probe.mjs` 验证。
- **隔离**：仅对 `gui/local-dev` 执行直接本地工具发现；不从开发实例读取正式凭据，不尝试访问托管公网端点，也不从本地检测推断 ChatGPT/Gemini 的实际工具数。发现失败、超时均不停止 MCP 引擎。
- **时效**：检测结果关联实例状态、当前 PID 和模式。服务启停、PID 变更、模式切换后旧结果失效；新运行实例自动检测。失败后至多按冷却时间重试，允许用户手动重查，避免三秒轮询产生连续高开销调用。

## 连接诊断四层

| 层级 | 实际证据 | 语义 |
|---|---|---|
| L1 本地引擎 | `state.actual` 及 `readiness.local` | 运行中和健康就绪分别显示；实例 PID 由管理核心核验 |
| L2 MCP 协议 | 独立 SDK `initialize`、`tools/list` | 发现状态、名称差异及实际数量 |
| L3 公网传输 | 管理协议的传输描述器、原有 `diagnose`（仅托管时显式调用） | 本地开发实例标记不适用；不将 OpenAI 诊断当 Gemini 诊断 |
| L4 远程客户端 | `state.readiness.remoteInvocation` | 没有经过 ChatGPT/Gemini 实际调用时始终“未验证” |

概览显示 PID、启动时间、运行时长、目标/回滚版本、工具数量、最新任务。连接页显示 `healthz`、`readyz`、MCP、控制平面、轮询失败数、当前实例传输能力、日志位置和仅本机有效的可复制地址。工具页可按名称搜索、类别和异常状态筛选。设置页保留 B2 的双模式和文件权限操作。

## 失败处理

MCP 超时后只结束 GUI 自己启动的检测子进程；管理子进程仍由共享管理客户端处理，修改操作绝不自动重试。真实引擎重启必须使用已有服务管理确认按钮。检测期间状态变化时，丢弃旧 PID / 旧模式的响应。不确定、过期、未部署的连接层级明确显示，不伪造成功。

## B3 验收

- `node tests/gui-b3-diff.mjs`：纯工具名称差集与同数量不一致。
- `node tests/gui-b3-faults.mjs`：非法实例、停止、进程身份与错误请求，不发生外部调用。
- `node tests/gui-b3-modes.mjs`：真实文件 14 / 终端 21、权限限制及实际工具调用，finally 恢复最初的模式、授权根和启动状态。
- `dotnet run --project tests/gui-contract -- <工作区>`：管理协议、状态、真实发现、超时。
- `dotnet run --project tests/gui-e2e`：离屏 WPF 启停、自动重探、GUI/TUI 联动、失败处理与窗口生命周期。
- `dotnet run --project tests/gui-visual`：四个页面、窄窗/150% 缩放及真实屏幕外渲染。
- 保留 B2 真实测试、隔离验证、发行包和正式服务健康检查。

详细证据及列项状态保存在 Git 忽略的 `test-runtime/`、`STATE.md` 和 `TASKS.md`。
